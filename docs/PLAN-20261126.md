# 改造方案（2026-11-26）

> 最后更新：2026-11-26 · 多端并发项目：决策只增不改，改动必须同批落档（见第八章、D34–D39）
>
> 依据：`docs/REVIEW-20261126.md`（问题清单与论证过程）与后续三轮评估（服务去留、个人收藏层、GitHub 同类项目调研）。
> 本文只保留**结论、决策与执行口径**，过程论证见评审文档，不再重复。

## 一、目标与边界

**目标（三件事）**

1. 采集从「常驻服务」变成「可调度的任务」，公开部署不再依赖长跑进程。
2. 数据从「两处存、直接覆盖写」变成「单一真源 + 可校验 + 原子写」。
3. 增加一层薄的个人收藏：localStorage 本地存、只显示自己收藏、可导出/导入。

**不变**

- 站点仍是纯静态 + 固定模板，采集只写数据、不改页面。
- 不引入账号、后端、数据库、定时同步。
- 采集只读公开接口：不登录、不下载视频、不绕过付费、不抓取私有收藏夹。

## 四、明确不做

1. 删除 `server.py`（它在本地仍有表单、回填、下线开关的价值，只降级为不对外）。
2. 真正的双站部署、账号体系、把 PAT 放进页面。
3. 把收藏写进公开仓库，或让个人数据目录进入 Pages 构建范围。
4. 继续维护 `topics/*.html` 旧模板。
5. 在个人层做全文检索、标签体系、笔记编辑器（属 linkding / wallabag / Karakeep 赛道）。
6. 依赖登录态抓取收藏夹、下载视频、或任何"免登录/去广告"式能力。
7. 引入模板引擎 / SSG 构建步骤（Hugo、Eleventy、Nunjucks 等）：会打破「零构建 + `file://` 可开 + 单页单样式」的现状，收益仅为"结构差异极大"的场景，本阶段不需要。
8. 为每个主题复制一套 `index/series/list/single.html`：页面数量 × 主题数，维护成本指数上升，且必然产生版本漂移。
9. M5 阶段做第 3 套主题或主题市场：2 套已足够验证契约，第 3 套等真实需求再议（见 D31）。

## 七、页面与数据分离 · 多主题模版（新增需求 2026-11-26）

### 7.1 现状判定

- **已分离**：数据层（`assets/data/index.js` + `assets/data/collections/*.js`）、页面层（5 个 html）、加载层（`assets/data-loader.js`）、采集层（`collector/`）四层清晰；采集端从不写页面，「页面与数据分离」这一原则基本成立。
- **未彻底 4 处**：
  1. 数据里带路由：`collection.page: "series.html?id=..."`，路由属表现层信息，却被采集端写进数据。
  2. 数据里带展示名：`source.platform` 存的是中文名（"B站""多平台"），前端靠中文键查 `PLAT_COLORS`，主题无法覆盖配色。
  3. 渲染逻辑重复：`cardHtml` 与详情模板在 4 个页面各写一份，且 `index.html` / `series.html` 未转义（见 D10）。
  4. 样式双轨：`assets/style.css` 与各页内联 `<style>` 都写颜色，内联优先级更高，主题 CSS 会被就地挡住。
- **结论**：页面与数据已分离，但**表现层没有抽象**。支持多主题的前提是先做第 3、4 项，并把第 1、2 项从数据里剥离（对应 D21–D24）。
- **已有基础（比预期好）**：`assets/style.css` 的 `:root` 已定义 12 个 token（`--bg/--surface/--text/--brand/--shadow/--radius` 等），且已有 `@media (prefers-color-scheme: dark)` 分支；页面内硬编码颜色集中在渠道徽标与占位封面渐变（4 个页面合计约 50 处，`single.html` 最多，23 处），`PLAT_COLORS` 重复在 3 个文件里。这意味着「纯 CSS 换肤」几乎零改造即可成立，真正的工作量在「抽渲染函数 + 消灭硬编码」。

### 7.2 分层目标（改造后结构）

```
assets/
├── data/             数据层：采集产出的纯数据，不含路由、不含样式、不存中文展示名
├── data-loader.js    加载层：读 ?id=、按需注入数据文件
├── render.js         视图层：数据 → 卡片/列表项/详情的 DOM 片段（唯一实现）
├── style.css         结构层：布局、网格、组件骨架、全局重置
└── themes/
    ├── default.css   设计 token：颜色 / 圆角 / 阴影 / 字号 / 间距 / 动效
    └── dark.css
```

页面只保留：`<link id="theme-css">`、容器、路由、少量页面级布局；不再出现硬编码颜色。

### 7.3 主题契约（硬约束）

- 主题 CSS **只允许**定义 token 变量 + 最多一份页面级局部样式。
- **禁止**在主题里写 JS、改 DOM、改页面结构；主题不承载任何业务逻辑。
- 新增主题 = ①复制 `default.css` 改名 → ②改变量值 → ③在主题注册表加一行；**不新增 HTML**。
- 加载方式：`<link id="theme-css" href="assets/themes/default.css">`，切换只改 `href`；选择存 `localStorage`；`?theme=` 仅作预览、不参与索引与分享；dark 主题与 `prefers-color-scheme` 联动。
- 防闪烁：`<head>` 内前置一小段脚本，按 `localStorage` 决定首个 `href`，避免主题闪一下再切换。
- 数据可选 `theme` 字段作为**单元级模板提示**（如将来"杂志版"单元），缺省用全局主题；该字段只影响渲染选择，不影响采集与校验。

### 7.4 与既有约束的关系

- 修订原「本页样式内联、只动该页」约定 → **「内联只写布局，颜色/圆角/阴影一律走 token；改布局仍只动该页」**。
- 与 D10 合并：抽 `render.js` 时一次性统一 `esc()`，一个改动同时解决 XSS 与视图层重复。
- 与 D18 合并：README / DEPLOY 同步补充 `assets/themes/` 目录与主题契约。
- 纯静态性质、Pages / Nginx 部署方式、采集端行为均不受影响。

### 7.5 收益、成本与风险

- **可分级推进**：
  - **A 级（纯 CSS 换肤）**：现有 `:root` token + dark 媒体查询已就绪，新增一套主题≈复制变量块；约 **0.5 人日**，不触碰任何 JS。
  - **B 级（表现层抽象）**：抽 `assets/render.js`、清掉页面内散落的硬编码颜色与 `PLAT_COLORS`、补主题注册与切换，约 **2–3 人日**，也是"新增主题不改 JS"这条契约真正成立的前提。
- **收益**：新增一套主题 ≤0.5 人日（只写 CSS）；卡片/详情改一次全站生效；为"按单元换版式"预留入口；顺带消灭 5 页里散落的颜色字面量。
- **成本**：B 级 2–3 人日（含 4 处渲染函数与内联样式迁移）；主题数量与维护成本线性相关，建议内置 ≤3 套。
- **风险**：迁移期间 5 页可能出现短暂样式不一致 → 以默认/暗色两套截图对比作为验收；主题覆盖不全会出现"半套主题" → 靠契约（token 必须全量）兜住。

- 不做主题编辑器 / 自定义 CSS 上传 / 主题市场；

- 不引入 CSS 预处理器或构建步骤。

## 十一、布局 token 化清单（D43，2026-11-26 追加）

### 11.1 前置：先合并重复声明

| `.site-footer` padding | 30/0/44 | 无覆盖 | 可 token 化 |

### 11.2 布局 token 建议值

**全局节奏**：`--layout-wrap`(1080px)、`--layout-gutter`(24px，移动 16)、`--layout-header-h`(60px，移动 54)、`--layout-section-gap`(56px)、`--layout-hero-pad`(68/0/34)、`--layout-hero-sub-pad`(8 / 4/0/18)、`--layout-facts-gap`(32px)。

**卡片与网格**：`--layout-topic-min`(290px，首页 260)、`--layout-video-min`(272px，合集 256)、`--layout-fav-min`(240px)、`--layout-card-pad`(18–20px)、`--layout-cover-ratio`(16/9，首页封面/视频缩略/播放器/公众号封面共用)、`--layout-desc-lines`(2)、`--layout-tag-lines`(2)、`--layout-badge-offset`(10–14px)。卡间距继续复用已有的 `--gap-card`(18px)。

**筛选与列表**：`--layout-filter-gap`(10px)、`--layout-filter-pad`(14/16)、`--layout-toolbar-max`(420px)、`--layout-pager-gap`(8px)、`--layout-empty-pad`(40–60px)。

**详情页（结构级，风险最高）**：`--layout-detail-cols`(`minmax(0,1.4fr) minmax(260px,1fr)`)、`--layout-detail-gap`(28px)、`--layout-article-max`(780px)、`--layout-xhs-cols`(`330px minmax(0,1fr)`)、`--layout-xhs-ratio`(3/4)、`--layout-ep-max-h`(400px)、`--layout-ep-nav-gap`(12px)。

**页脚与收藏面板**：`--layout-footer-pad`(30/0/44)、`--layout-fav-body-pad`(12/14/14)、`--layout-mine-tool-gap`(8px)。

### 11.3 哪些进主题、哪些必须独立布局维度

- **可进主题（低风险）**：网格密度、卡片内边距、卡间距、封面比例、摘要行数、hero 高度、区块间距、页脚高度。示例：科技风 `topic-min:240px` + `card-pad:12px`（高密度），古典风 `topic-min:320px` + `card-pad:24px`（疏朗），二次元 `cover-ratio:4/3`。
- **不可进主题（结构级）**：详情页双栏比例、小红书图文并排、公众号栏宽、剧集侧栏高度 → 应做独立 `data-layout`（standard / dense / magazine）+ `assets/layouts/*.css`，主题切色、布局切形，互不绑定。
- **不建议**：每套主题复制一份页面 CSS/HTML。6 套主题会变 6 份维护负担，违背页面/数据/主题分离。

### 11.4 实施顺序与验收

1. 合并 11.1 的重复声明，统一口径；
2. `style.css` 的 `:root` 增加布局 token 默认值（颜色/字体 token 不动）；
3. 替换 `style.css` 43 处布局声明 + 四页内联剩余布局值；媒体查询断点保留字面量（CSS 变量不能进 `@media`）；
4. `docs_check.py` 口径拆分为「颜色/字体 token 全量对齐」+「布局 token 白名单子集」，否则主题覆盖布局会误报；
5. 先给 2 套主题配布局值（tech dense、classical magazine），其余沿用默认；
6. 验收矩阵：default+standard、tech+dense、classical+magazine 三组截图 + 移动端一组；`test_pages.py`/`test_render.js` 的 class 断言不得改动。

**成本/风险**：合并+定义+替换约 1–1.5 人日；只做主题级覆盖约 0.5 人日。主要风险是页面内联优先级、主题 token 自检口径、主题×布局组合破版。

- **筛选分组**：首页与「我的」的筛选条改为卡片式纵向分组——类型 / 平台 / 标签各占一行，行间用虚线分隔，左侧固定小标签；搜索单独一行、右对齐（移动端占满整行）。
- **搜索框**：胶囊形、内置放大镜图标（内联 SVG），聚焦时品牌色描边 + 3px 柔光环；宽度 320px，600px 以下 100%。
- **顺手修正**：类型 chip 点击时原逻辑会清掉全站所有 `.chip` 的 active（把标签/平台筛选也清空），现限定在 `#filter-bar .chip[data-filter]` 内；平台/标签分组在无数据时隐藏，有数据时自动出现。
- **验收**：500px 宽下详情页播放器 468×263（16:9）、目录紧跟播放器并可横滑，无横向溢出；首页筛选四行分组与胶囊搜索框、我的页分组均截图通过；node 12 例、Python 39 例、verify/docs-check 通过。
