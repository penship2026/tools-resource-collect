## 一、发布用文案（短版，约 600 字）

**标题备选**

1. 37 小时，我把一条视频做成了一整个网站
2. 从一条视频号到 12 个主题清单：我的「集页」诞生记
3. 收藏夹吃灰的第 100 天，我干脆自己做了一个站
4. 不会设计也能做：两天上线一个能换 6 套皮肤的内容站

**正文**

前天凌晨一点，我刷到一条讲「免费学拼音网站」的视频号。

视频很有意思，但它的内容只在微信里能看。我顺手去 B站 搜了同款系列，发现同一支账号把内容分发到了多个平台——那一刻我突然意识到：**我缺的不是内容，是把内容收成一份清单的地方。**

于是有了「集页」：一集一页，把值得收藏的视频和图文收成主题清单。

最开始它只是我手工拼的几个 HTML。后来我干脆把「找内容—去重—写数据—出页面」交给一套纯规则程序：不登录、不下载视频、不绕过付费，只读各平台的公开搜索与详情接口。采集只写数据，页面是固定模板，所以站点始终是纯静态的，打开很快。

中途我踩了两个印象最深的坑：

一是视频号能分享、却不能在浏览器里直接播；抖音的搜索页会弹验证码。最后我把 B站 作为主数据源，公众号和小红书用「链接采集」补齐。**不是所有平台都要硬接，先想清楚哪些内容值得接。**

二是最早的数据写入是直接覆盖文件。一次异常中断就可能让整站变空白。后来改成「先写临时文件、再原子替换、覆盖前留快照」，还加了一个自检命令，每次采集完先验一遍索引和文件是否对得上。

第二天下午，我停下来做了一次全项目评审，列出 18 个问题，从「默认部署会把 .git 和备份目录公开」到「标题没转义可能执行脚本」。然后按优先级排期：先止血，再安全，再任务化，最后才是主题和美化。**先让站活着、安全、可持续更新，再谈好看。**

现在的集页：
- 12 个采集单元，8 个合辑 + 4 个单条
- 4 个浏览页 + 1 个本机采集台
- 6 套主题：默认、深色、科技、学院、古典、二次元
- 单条 B站 链接如果命中 UP 主合集，一次就能展开全集合集
- 详情页的分集目录就在播放器下方，左右滑动、展开全部、点一集直接在当前页切播
- 390px 手机屏实测无横向溢出

最让我满意的不是「做了多少功能」，而是它现在真的能自己更新：GitHub Actions 每天北京时间 07:00 采集一次，数据有变化才提交；我不用一直开着电脑。

如果你问我这两天最大的感受——

**做产品最难的从来不是把功能堆上去，而是知道什么先做、什么不做，以及什么时候停下来检查。**

集页还在长。下一步我想把「主题清单」做得更像一本可以翻阅的册子，而不是一个列表。

## 三、完整创作过程

### 0. 起点：一条只能跳转的视频（11-25 01:12）

最初的需求很具体：把「每天挖掘一个神奇网站」这类主题视频收成一个聚合页。

我先做了渠道可行性分析：

- 视频号分享页没有可播放的 `video`，只给封面和二维码，提示「扫码前往微信观看」；
- B站 搜索页可直接访问，视频能嵌播，确定为主数据源；
- 抖音搜索页弹验证码，风控成本高，暂不纳入。

这一步没有写页面，只回答了一个问题：**内容从哪里来，能不能稳定地来。**

### 1. 第一版：从手工页面到纯规则程序（01:25–01:58）

第一版是手工拼的 `index.html` + 单个主题页 + 一份集中数据。

很快我意识到两个问题：手工做第二个主题就会重复劳动；数据放在一个文件里，新主题会把旧主题覆盖。

于是把流程改成纯规则程序：关键词 → B站公开搜索 → 聚类同系列 → 写入独立数据文件。全程不用 AI，标题必须完整包含关键词，重复条目按 BV 号去重。

### 2. 数据模型重做：每次采集是一个「单元」（08:09–08:29）

这是整个项目最重要的一次架构调整。

- 每次采集 = 一个独立单元，存 `assets/data/collections/<id>.js`；
- 索引只存单元元信息和显示开关；
- 单元可单独重采、单独下线，不互相覆盖。

中间踩了一个很隐蔽的坑：浏览器里 `const` 声明的全局变量不会挂到 `window`，页面读不到索引，首页显示 0 个主题。改成 `window.X = ...` 才解决。

### 3. 从「视频站」到「集页」（11-26 00:11）

接公众号和小红书之后，原来的名字「神奇网站挖掘机」已经盖不住内容形态了。

候选有 集页 / 拾集 / 集录 / 清单集，最后选「集页」：**一集一页**，视频的「集」和图文的「页」双关。

同一天补齐了按渠道分模板的详情页：B站 视频双栏 + 官方 iframe、公众号单栏阅读版式、小红书图左文右、其他渠道兜底。

### 4. 三渠道采集：不是所有平台都能「搜」（07:20–08:35）

B站 有公开搜索接口；公众号和小红书没有稳定的公开搜索，只能：

- 用搜索引擎做 `site:` 检索找候选链接；
- 公众号再逐条抓正文、作者、日期；
- 小红书只收标题和原文链接，正文需登录。

所以产品上给了三种入口：按链接、批量链接、按主题。小红书风控失败时，允许手工补录标题，不让用户卡死在采集环节。

### 5. 停下来评审：18 个问题与一张排期表（10:30–13:10）

功能能跑之后，我没有继续加功能，而是做了一次全项目评审。

评审覆盖 README、部署文档、全部采集代码和 5 个页面，实测了敏感路径、接口鉴权、数据一致性和页面转义。最终列出 18 个问题，按 P0–P3 分级。

接着把改造拆成里程碑：

| 里程碑 | 目标 | 一句话 |
|---|---|---|
| M0 止血 | 转义、原子写、损坏识别 | 先别让一次异常把站弄没 |
| M1 安全 | 仅本机、公网口令、静态白名单 | 别把 `.git` 和备份挂在公网 |
| M2 任务化 | Actions + topics.yml + 本机兜底 | 不常驻进程也能更新 |
| M3 个人层 | localStorage 收藏 + 导出导入 | 最薄的一层，不做账号 |
| M4 质量 | 自检、fixtures、CI、文档自检 | 让问题在提交前暴露 |
| M5 主题化 | token、render.js、6 套主题 | 最后再谈好看 |
| M6 可选 | 私有同步 / dispatch | 连续用一个月再启动 |

这张表的顺序比功能本身更重要：**先活着，再安全，再自动，再体验。**

### 6. 六套主题与「我的」页：把表现层抽出来（16:00–次日 06:20）

主题不是复制 6 套 HTML，而是：

- 颜色、圆角、阴影、字体全部收敛成 token；
- 卡片/列表/详情渲染收进唯一的 `assets/render.js`；
- 新增主题 = 加一个 CSS + 注册一行，不改 JS/HTML。

第一版科技风太像深色，被否掉；第二版做成赛博霓虹，还是不对；第三版改成拉勾式浅色科技风才过。二次元主题则是樱花粉 + 天蓝 + 大圆角。**审美这件事，确实要允许自己改三版。**

「我的」页也只做最薄的一层：本机收藏、导出/导入、可自定义标题/副标题/入口名、独立主题，不做账号、不做同步。

### 7. 最后 24 小时：细节把体验拉开（06:30–14:10）

- B站 单链采集命中 UP 主合集时，用一次 view 响应展开全集合集，不逐集请求，避免风控；
- 详情页的分集目录移到播放器下方，横向滑动、展开全部、点集切播；
- 首页与「我的」筛选按类型/平台/标签分组，搜索框改成胶囊样式；
- 采集页「已有单元」每页 10 条，避免页面被拉得很长；
- 修掉移动端播放器溢出：网格子项 `min-width:auto` 被 53 个分集 chip 撑宽，加 `min-width:0` 和窄屏单列后恢复 16:9；
- 用 Playwright 在 390×844 真机视口复验，详情页 `scrollWidth=390`，播放器 358×201。

### 8. 收尾：把「遗留」一条条清掉（14:10 前）

最后做了一次遗留清理：

- 采集服务改多线程，长采集不再阻塞页面；
- 单条/批量采集改用链接派生稳定 id，不再靠标题猜；
- 索引改为从单元文件重建，不再双写；
- 接口 id 加白名单，超长输入保留最近 8000 字并标注；
- 9 个存量单元的旧文案统一。

验收：44 个 Python 用例、12 个 node 用例、`--verify` 12 个单元 0 问题、文档自检通过。

## 四、这次做对了什么

1. **先定边界，再写代码。** 采集只读公开接口、只写数据、不改页面；不做账号、不做数据库、不做下载。边界越清楚，后面越快。
2. **把「数据」当成产品资产。** 单元独立文件、原子写、快照、自检，这些不显眼，但决定了站能不能长期活着。
3. **允许停下来评审。** 18 个问题里，真正会致命的都是「默认部署」和「异常写入」这种不性感的地方。
4. **排期按风险，不按兴奋度。** 先 M0/M1，把主题和美留到最后；如果反过来，很可能做了一个好看但随时会挂的站。
5. **审美可以迭代，但契约要硬。** 主题可以改三版，但 token 必须全量对齐、新增主题不能改 JS。

## 五、踩坑清单（可复用）

- 浏览器里 `const` 全局不挂 `window`，页面读不到数据；
- 视频号分享页不能浏览器播放；抖音搜索有验证码；
- B站 搜索 API 需要 `buvid3`，否则第二次请求被风控；
- 数据直接覆盖写，一次中断就能让全站空白；
- 横向滚动容器会把 CSS Grid 子项撑爆，`min-width:0` 是救命字段；
- `git push` 遇 HTTP2 framing，可临时用 `git -c http.version=HTTP/1.1`；
- 小红书正文需登录，采集失败要留「手工补录」出口。

## 六、下一步

- 把主题清单做成更像「册子」的翻阅体验；
- 继续补真实设备上的移动端细节；
- 主题/布局 token 分维度，让「换色」和「换版式」解耦；
- 保持零构建、纯静态、可 `file://` 打开的底线。
