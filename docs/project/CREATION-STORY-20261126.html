37 小时，我把一条视频做成了一整个网站 前天凌晨一点，我刷到一条讲「免费学拼音网站」的视频号。 视频很有意思，但它的内容只在微信里能看。我顺手去 B站 搜了同款系列，发现同一支账号把内容分发到了多个平台——那一刻我突然意识到：我缺的不是内容，是把内容收成一份清单的地方。 于是有了「集页」：一集一页，把值得收藏的视频和图文收成主题清单。 最开始它只是我手工拼的几个 HTML。后来我干脆把「找内容—去重—写数据—出页面」交给一套纯规则程序：不登录、不下载视频、不绕过付费，只读各平台的公开搜索与详情接口。采集只写数据，页面是固定模板，所以站点始终是纯静态的，打开很快。 中途我踩了两个印象最深的坑： 一是视频号能分享、却不能在浏览器里直接播；抖音的搜索页会弹验证码。最后我把 B站 作为主数据源，公众号和小红书用「链接采集」补齐。不是所有平台都要硬接，先想清楚哪些内容值得接。 二是最早的数据写入是直接覆盖文件。一次异常中断就可能让整站变空白。后来改成「先写临时文件、再原子替换、覆盖前留快照」，还加了一个自检命令，每次采集完先验一遍索引和文件是否对得上。 第二天下午，我停下来做了一次全项目评审，列出 18 个问题，从「默认部署会把 .git 和备份目录公开」到「标题没转义可能执行脚本」。然后按优先级排期：先止血，再安全，再任务化，最后才是主题和美化。先让站活着、安全、可持续更新，再谈好看。 现在的集页： - 12 个采集单元，8 个合辑 + 4 个单条 - 4 个浏览页 + 1 个本机采集台 - 6 套主题：默认、深色、科技、学院、古典、二次元 - 单条 B站 链接如果命中 UP 主合集，一次就能展开全集合集 - 详情页的分集目录就在播放器下方，左右滑动、展开全部、点一集直接在当前页切播 - 390px 手机屏实测无横向溢出 最让我满意的不是「做了多少功能」，而是它现在真的能自己更新：GitHub Actions 每天北京时间 07:00 采集一次，数据有变化才提交；我不用一直开着电脑。 如果你问我这两天最大的感受—— 做产品最难的从来不是把功能堆上去，而是知道什么先做、什么不做，以及什么时候停下来检查。 集页还在长。下一步我想把「主题清单」做得更像一本可以翻阅的册子，而不是一个列表。 #独立开发 #个人项目 #网站开发 #内容聚合 #B站 #公众号 #小红书 #程序员日常 #产品设计 #从0到1

The making

完整创作过程

按真实时间线整理，保留了那些不性感的转折与返工。

11-25 01:12

起点：一条只能跳转的视频

需求很具体：把「每天挖掘一个神奇网站」这类主题视频收成一个聚合页。先做渠道可行性：视频号分享页没有可播放的 video；B站 可直接访问、可嵌播；抖音搜索弹出验证码。没有先写页面，只回答一个问题——内容从哪里来，能不能稳定地来。

先验证渠道，再设计页面。这个顺序省下了后面很多返工。
01:25 — 01:58

第一版：从手工页面到纯规则程序

第一版是手工拼的首页 + 单主题页 + 一份集中数据。做第二个主题时立刻发现会重复劳动，数据放在一个文件里还会互相覆盖。于是改成纯规则流程：关键词 → B站公开搜索 → 聚类同系列 → 写入独立数据文件，全程不用 AI。

08:09 — 08:29

数据模型重做：每次采集是一个「单元」

整个项目最重要的一次架构调整。每个采集单元独立一个数据文件，索引只存元信息和显示开关；单元可以单独重采、单独下线，不互相覆盖。

踩坑：浏览器里 const 声明的全局变量不挂 window，页面读不到索引，首页显示 0 个主题。改成 window.X = ... 才解决。
11-26 00:11

从「视频站」到「集页」

接入公众号和小红书之后，原名已经盖不住内容形态。候选有 集页 / 拾集 / 集录 / 清单集，最后选「集页」：一集一页，视频的「集」和图文的「页」双关。

07:20 — 08:35

三渠道采集：不是所有平台都能「搜」

B站 有公开搜索接口；公众号和小红书没有稳定公开搜索，只能用搜索引擎做 site: 检索，公众号再抓正文，小红书只收标题和链接。产品上因此给了三种入口：按链接、批量链接、按主题。风控失败时允许手工补录，不让人卡死在采集环节。

10:30 — 13:10

停下来评审：18 个问题与一张排期表

功能能跑之后没有继续加功能，而是做了一次全项目评审：通读文档、采集代码和 5 个页面，实测敏感路径、接口鉴权、数据一致性、页面转义。最终列出 18 个 P0–P3 问题，并拆成 M0 止血 → M1 安全 → M2 任务化 → M3 个人层 → M4 质量 → M5 主题化的顺序。

16:00 — 次日 06:20

六套主题与「我的」页

主题不复制 6 套 HTML：颜色、圆角、阴影、字体收敛成 token，卡片/列表/详情渲染收进唯一的 render.js。新增主题 = 一个 CSS + 注册一行。科技风改了三版才过：太像深色 → 赛博霓虹 → 最后改成拉勾式浅色科技风。

审美可以迭代，但契约要硬：token 必须全量对齐，新增主题不能改 JS。
06:30 — 14:10

最后 24 小时：细节把体验拉开

B站 单链命中合集时一次展开全集合集；详情页分集目录移到播放器下方，可横滑、展开、点集切播；筛选项按类型/平台/标签分组；采集页单元列表分页；390px 手机屏复验，播放器 358×201、无横向溢出。

14:10 前

收尾：把「遗留」一条条清掉

采集服务改多线程、单条/批量改用链接派生稳定 id、索引改为从单元文件重建、接口 id 加白名单、超长输入保留最近 8000 字并标注。验收：44 个 Python 用例 + 12 个 node 用例 + 数据自检 0 问题 + 文档自检通过。

The schedule

排期不是按兴奋度，是按风险

真正致命的，往往是最不性感的「默认部署」和「异常写入」。

里程碑目标一句话
M0止血转义、原子写、损坏识别——先别让一次异常把站弄没
M1安全仅本机、公网口令、静态白名单——别把 .git 和备份挂公网
M2任务化Actions + topics.yml + 本机兜底——不常驻进程也能更新
M3个人层localStorage 收藏 + 导出导入——最薄一层，不做账号
M4质量自检、fixtures、CI、文档自检——让问题在提交前暴露
M5主题化token、render.js、6 套主题——最后再谈好看
M6可选私有同步 / dispatch——连续用一个月再启动
What I learned

做对了什么，踩了哪些坑

可以复用的是方法，不是功能。

这次做对的 5 件事

  • 先定边界再写代码：只读公开接口、只写数据、不做账号和数据库。
  • 把数据当产品资产：独立文件、原子写、快照、自检。
  • 允许停下来评审：18 个问题里最致命的都不显眼。
  • 排期按风险：先止血和安全，把美留到最后。
  • 审美可迭代，契约要硬：主题能改三版，token 必须全量对齐。

踩过的 7 个坑

  • const 全局不挂 window，页面读不到数据。
  • 视频号分享页不能浏览器播放，抖音搜索有验证码。
  • B站 搜索 API 缺 buvid3 会被风控。
  • 直接覆盖写，一次中断就能让全站空白。
  • 横向滚动容器会把 Grid 子项撑爆，min-width:0 救命。
  • git push 遇 HTTP2 framing，可临时切 HTTP/1.1。
  • 小红书正文需登录，采集失败要留手工补录出口。

做产品最难的从来不是把功能堆上去，而是知道什么先做、什么不做，以及什么时候停下来检查。

What's next

下一步，不着急加功能

更像一本册子把主题清单的翻阅体验做深，而不是继续堆列表。
真机细节继续补移动端真实设备上的滑动、字体与点击手感。
换色与换版式解耦主题管颜色，布局管疏密，互不绑定。
守住底线零构建、纯静态、可 file:// 打开、只读公开内容。
