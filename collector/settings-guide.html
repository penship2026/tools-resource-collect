设置页填写说明

本页说明「采集设置」页面各字段怎么填、保存后会发生什么，以及常见失败原因。

← 返回设置页 采集页

一、先看三件事

卡片默认收起点击板块或主题标题可收起整个区域；区域展开后，内部卡片仍默认收起，点卡片标题栏再展开。
单卡或整页保存点卡片「编辑」后可「保存本卡」只提交这一张；底部「保存全部改动」用于批量保存和删除落盘。
采集才会写数据保存配置不会采集；「立即执行」会真实抓取并写入数据，不是预览。
设置页只改本机的 sections.yml 与 topics.yml；线上定时采集由 GitHub Actions 执行。

二、板块怎么填

板块决定首页的筛选分组，也决定主题归属。每个主题必须挂在一个板块下。

字段填写规则说明
名称2–12 个字首页筛选和设置页卡片显示的名字。
说明最多 60 字建议写年龄段和内容范围；自定义板块不填会有提示，但不阻止保存。
排序整数板块卡片按排序升序显示；改完排序离开输入框后立即重排，保存后写入配置。
显示勾选 / 不勾选控制该板块的单元是否在首页展示；不控制是否采集。
板块 id小写字母、数字、短横创建后不可改；主题归属和采集单元都依赖它。
年龄段只读「婴幼儿养护」「学前教育」「中小学教育」三段边界固定，不能删、不能改。

新增板块

  1. 点「+ 新增板块」，先输入板块 id，再输入名称。
  2. 新板块默认全龄、启用、无说明；需要时展开卡片补说明。
  3. 点「保存本卡」或「保存全部改动」后才会写入配置文件。
自定义板块只能全龄；0–18 岁的三段保留板块不能删除，也不能改年龄段。已有采集单元的板块删除后会导致自检失败，不建议删。

搜索与独立展开

板块区支持按名称、id、说明搜索，主题区支持按标题、主题 id、归属板块、must/any 关键词和渠道搜索。搜索只筛选卡片，不影响保存内容。点击「板块」或「主题」标题可收起整个区域，再点一次展开；区域内的「全部展开 / 全部收起」只控制当前区域的卡片，两者互不影响。

三、主题怎么填

一个主题对应一个采集单元；主题 id 同时是单元 id，创建后不可改。

字段填写规则说明
must1–4 个，逗号分隔每个关键词都必须出现在候选标题、简介或分P标题中。
any0–5 个，逗号分隔至少命中一个；留空表示不限制。
渠道多选可同时勾选 B站、公众号、小红书；至少保留一个。B站走视频搜索，公众号/小红书走图文检索。
显示 / 采集勾选 / 不勾选停用后不参与自动采集，已有单元也不会在首页展示。
主题名称编辑态可改点「编辑」后可改标题；「保存本卡」只更新这个主题。
归属板块编辑态下拉选择从现有板块中选择；保存后主题归到新板块。

关键词怎么选

  • 第一个 must 同时是搜索词，建议放最宽的主词，例如「大模型」；后面的 must 只参与过滤。
  • must 太长容易抓不到；标题措辞稍有变化就会失败。
  • any 用来补同义词，例如「对比 / 评测 / 横评」。
  • 匹配会忽略大小写、全角半角、空格和常见标点。

已有单元的 author 锁

已有单元重采时只认原作者。原作者本次没有命中，就本次不更新，不会自动切换到其他 UP 主。这是防止系列串台；需要换作者只能人工处理，页面不提供解锁开关。

新增主题

  1. 点「+ 新增主题」，依次填写板块 id、主题名称、must 关键词、主题 id。
  2. 新主题默认渠道 bilibili、any 为空、启用。
  3. 保存前再展开卡片补 any 或渠道。

四、保存与提示

  • 保存本卡：点卡片右上角「编辑」，字段变为可编辑；改完点「保存本卡」，只提交这一张板块或主题，其他卡片未保存的改动不会被带走。
  • 取消：放弃这张卡片的改动并恢复为上次保存的值；新增卡片取消后会从页面移除。
  • 保存全部改动：批量保存，一次提交全部板块和主题，写入 sections.yml / topics.yml，并执行一次全量数据自检。单卡已可独立保存，这里主要用于一次改多张以及删除落盘。
  • 单卡保存后卡片退出编辑态；如果还有其他未保存卡片，顶部仍会显示「有未保存改动」。
  • 删除板块或主题仍属于整页改动，需要再点「保存全部改动」才会落盘。
  • 以下情况会给出提示但不阻止保存：自定义板块没有说明；启用板块下没有启用主题。

五、线上定时

项目当前行为
cron只读，来自 .github/workflows/update-data.yml，当前为 0 23 * * *（北京时间每天 07:00）。
每主题页数只读，当前默认 3 页；「立即执行」也使用这个页数。
导出 cron 片段只生成 YAML 文本，不会修改 workflow；需要自己粘贴并提交。
立即执行真实采集并写数据，串行执行；页面最多轮询约 4 分钟，超时后任务可能仍在后台继续。
「立即执行」不是 dry-run。确认当前配置和作者锁符合预期后再点。

六、数据同步 Git

只同步采集数据，不提交代码、配置和文档。固定提交到 origin/main。

  • 只允许 assets/data/index.js 与 assets/data/collections/*.js。
  • 推送前要求当前分支是 main；开发分支会显示阻塞。
  • 要求 Git 已配置 user.name 和 user.email；身份显示「已配置」只代表 name 存在，email 仍会在预检时校验。
  • 要求没有合并/变基/拣选状态，白名单内不能有删除文件，本地不能落后远端。
  • 「预览变更」只做本地预检；「同步推送数据」会先 fetch，再做校验、commit 和 push。
  • 推送失败但已本地 commit 时，状态可能是「已提交未推送」，需要处理网络或凭据后重试。

七、本机调度

当前版本由 GitHub Actions 固定运行，本机调度默认关闭；页面不提供开启按钮。停用线上 cron 后才适合改用本机 launchd，页面本身不做切换。

八、常见问题

现象处理
页面打不开先确认本机服务已启动：python3 collector/server.py；手机访问用 --lan 并连同一 Wi-Fi。
保存返回 403CSRF / Origin 校验失败。刷新页面拿新 token；服务重启后旧页面也会失效。
保存提示板块 id 非法板块 id 只能用小写字母、数字和短横。
保存提示 section 不存在主题引用了已删除的板块；先恢复板块或把主题改到现有板块。
全部主题失败看「立即执行」日志：关键词 must 未全命中、原作者无命中，或网络请求失败。
某个主题一直不更新已有单元作者锁生效：原作者本次没有新内容时不会切换作者。
Git 推送被阻塞看预览里的 blockers：分支不是 main、身份缺失、远端领先、数据文件删除或没有数据变更。

九、推荐操作顺序

  1. 先加板块，再给板块加至少一个启用主题。
  2. 保存全部改动，确认页面没有红色错误。
  3. 需要验证采集时，先看关键词和作者锁，再点「立即执行」。
  4. 确认数据无误后，切到 main，用 Git 面板预览并推送数据。
  5. 线上首页更新后，再检查板块筛选和单元归属。
