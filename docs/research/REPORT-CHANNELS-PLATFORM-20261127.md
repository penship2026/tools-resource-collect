# 视频号收藏与播放方案（合并版）

- 文档状态：2026-11-28 合并更新。本文是视频号收藏、H5 显示与小程序播放的唯一结论文档。
- 使用方式：后续独立会话可直接以本文为任务说明，先确认“通用收藏”还是“自有视频号播放”，再决定是否落地。
- 适用项目：集页 `tools-resource-collect`
- 文档范围：视频号链接识别、收藏数据、H5 显示、现有单链接采集适配、微信小程序内播放、主体与参数限制、合规边界
- 结论性质：方案评估，不含业务代码实现

## 一、结论摘要

**视频号可以收藏和索引，但不能把“任意分享链接”稳定变成“H5 内播放”或“小程序内播放”。**

分三层看：

1. **H5 页面**：只能做收藏、标题/作者/备注整理、复制链接和回微信打开提示。不能 iframe 嵌入，不能用普通 `<video>` 播放，直接 `location.href` 跳转容易白屏。
2. **现有单链接采集**：不能原样复用。当前会把视频号链接误判成公众号，且视频号分享页没有公众号文章所需的元数据；最多走手工补录，但记录仍会标成“公众号文章”。
3. **定制微信小程序**：可以实现“小程序内播放”，但只对能取得 `feed-id` 或 `feed-token` 的视频成立。普通分享链接不包含这些参数，任意他人视频也无法自动获取；非同主体内容还要求非个人主体小程序，并依赖人工、24 小时内复制的 `feed-token`。

因此，产品上应分成两类：

- **通用视频号收藏**：做索引和播放入口，不承诺站内播放；H5 或小程序都可以承载。
- **自有/关联视频号内容**：可以用小程序 `channel-video` 做完整的小程序内播放。
- **任意他人视频号 + 小程序内播放**：只能逐条人工补 `feed-token`，不适合作为通用产品承诺。

## 二、平台事实

### 2.1 H5 分享链接不是普通网页

视频号单条视频通常可以在分享菜单复制 `https://weixin.qq.com/sph/...` 形态的链接，但该链接主要服务于微信内分享：

- 外部浏览器不能稳定打开，常见白屏或“请在微信打开”的中间页；
- 不能作为 `<iframe src>` 或 `<video src>` 使用；
- 在 H5 中直接跳转，用户体验和成功率都不可控；
- 最稳的动作是复制链接，由用户回到微信聊天中打开。

### 2.2 没有公开的视频号内容 API

微信开放能力主要覆盖直播、带货、商家、橱窗、视频号助手等场景，不提供“按关键词搜索公开视频”或“批量获取公开视频元数据”的通用接口。

因此不能像 B站一样做自动搜索、自动抓标题/封面/作者/播放量，也不能依赖非公开页面接口或登录态做批量采集。

### 2.3 小程序的两种官方能力

微信小程序提供两种打开视频号视频的方式：

| 能力 | 作用 | 关键参数 | 主体/权限 | 是否小程序内播放 |
| --- | --- | --- | --- | --- |
| `wx.openChannelsActivity` | 跳转到指定视频号的视频页 | `finderUserName`、`feedId` | 无主体限制 | 否，跳出小程序 |
| `channel-video` 组件 | 在小程序内嵌视频号视频，无弹窗跳转 | 同主体：`feed-id` + `finder-user-name`；非同主体：`feed-token` | 非同主体要求非个人主体小程序 | 是 |

#### `channel-video` 的限制

- 基础库 2.25.1 起支持，低版本需兼容。
- 同主体可用 `feed-id` + `finder-user-name`，同主体可自动播放。
- 非同主体从基础库 2.31.1 起支持，但只对**非个人主体小程序**开放，且强制 `autoplay=false`。
- 非同主体必须使用 `feed-token`。
- 暂不支持纯图片视频号内容。

#### `feed-token` 的获取方式

`feed-token` 不是从分享链接里自动解析出来的，而是人工获取：

1. 登录 MP 平台，在「设置-基本设置-隐私与安全」打开「获取视频号视频 ID 权限」。
2. 在手机端打开目标视频号视频，通过分享菜单选择「在小程序中引用该视频」。
3. 复制生成的 `feed-token`，再填进小程序或后台。

官方说明的硬限制：

- 开关打开后 **24 小时内生效**，失效后移动端不再展示复制入口；
- 开关只对当前操作者生效，换一个开发者/运营人员就看不到入口；
- `feed-token` 是逐条视频获取，不是账号级批量能力；
- `feed-token` 本身的长期有效期官方没有作出长期承诺，需要按实际场景验证。

#### `feedId` 的限制

`feedId` 需要在视频号助手「动态管理」里获取，主要对应自己发表的视频。官方文档对 `feed-id` 的说明是“视频号必须与当前小程序相同主体”，因此不能把它当成任意公开视频的通用参数。

### 2.4 “仅微信内展示”不能做硬限制

《微信外部链接内容管理规范》将“无正当理由通过技术手段限制页面浏览渠道，导致微信内展示效果和其他浏览器展示效果实质性不一致”列为恶意对抗行为。

所以可以针对微信环境做提示和体验增强，但不能把页面核心内容锁死为“只有微信能看”。更合适的做法：

- 微信内：提示复制链接后回聊天打开；
- 微信外：页面仍可访问，提示“视频号内容需回微信观看”；
- 收藏、编辑、导出在两端都可用。

## 三、现有项目适配性

### 3.1 链接识别会把视频号误判成公众号

当前 `collector/platforms.py` 的 `_HOST_RULES` 把 `weixin.qq.com` 整体识别为 `wechat`。实测结果：

```text
https://weixin.qq.com/sph/AKSHB3      -> wechat / 公众号
https://channels.weixin.qq.com/       -> wechat / 公众号
https://finder.video.qq.com/          -> 未识别
https://mp.weixin.qq.com/s/abc        -> wechat / 公众号
```

如果直接复用现有单链接采集：

- `/sph/` 链接会进入 `fetch_wechat()`，而该适配器读取的是公众号文章页变量（`msg_title`、`nickname`、`msg_cdn_url` 等）；
- 视频号分享页通常是前端壳，通常取不到标题，报“未能解析出公众号文章标题”；
- 如果壳页碰巧带有通用 `og:title`，还可能生成一条标题错误的“公众号文章”；
- `finder.video.qq.com` 会直接进入“暂不支持该链接”。

### 3.2 手工补录能建记录，但语义是错的

现有采集页的手工补录只在 `fetch` 抛错时生效。即使用户填了标题成功建记录，落库仍是：

```text
platform: wechat
kind: article
```

带来的问题：

- 卡片显示“公众号”徽标，不是“视频号”；
- 详情页走公众号模板，显示“公众号 · 文章”“阅读原文”；
- 没有“需回微信观看”的提示；
- 不能按视频号渠道筛选，导出/导入语义也不对。

### 3.3 显示层没有视频号模板

`assets/render.js` 的平台映射只有 `bilibili / wechat / xhs / multi`。即使数据里写入 `platform: channels`：

- `platLabel('channels')` 会退回原始字符串 `channels`；
- 颜色退回默认黑色；
- 详情页走 `renderGeneric`，按钮仍是普通外链；
- 点击 `v.url + target=_blank` 在普通浏览器里可能白屏，不会出现“回微信打开”的提示。

### 3.4 个人收藏模型不适合直接收站外内容

`assets/personal.js` 当前是“只收藏站内已有条目”，快照以 `unit + key` 为核心，没有独立的 `platform/source` 字段，详情跳转依赖站内 `unit`。

视频号属于站外内容，直接塞进 `jiye.mine.v1` 会导致：

- 没有对应 `unit`，详情页无法按现有逻辑跳转；
- 平台徽标退回默认渠道；
- 合集/板块归属不成立；
- 导入导出与现有收藏快照语义混杂。

更稳的是独立数据层，例如 `jiye.channels.v1`，或独立“视频号收藏”分区。

### 3.5 结论：现有单链接采集不是“改个提示”就能用

只加一句“需在微信内查看”不够，因为：

- 链接仍会被识别成公众号；
- 记录仍会以公众号文章落库；
- 详情仍会走公众号模板；
- 普通外链仍会直接跳转。

最少需要同时处理：渠道识别、采集降级、平台映射、详情模板、个人数据归属这五件事。

## 四、路线对比

| 路线 | 采集方式 | 显示/播放 | 主要限制 | 工作量 | 建议 |
| --- | --- | --- | --- | --- | --- |
| A. H5 独立收藏页 | 粘贴链接，手工标题，选填作者/封面/备注 | 卡片列表、复制链接、回微信打开 | 不能站内播放，不能自动抓元数据 | 低 | **通用收藏首选** |
| B. 小程序 + 自有/关联视频号 | 自有视频号助手获取 `feed-id` | `channel-video` 小程序内播放 | 仅同主体/关联主体，需小程序主体与审核 | 中 | **自有内容首选** |
| C. 小程序 + 非同主体 `feed-token` | 逐条人工复制 `feed-token` | `channel-video` 内嵌播放 | 非个人主体、24 小时权限、逐条人工、token 长期有效性待验证 | 中高 | 仅少量固定内容可做 |
| D. 小程序 + 仅跳转 | 链接/`feedId` | `wx.openChannelsActivity` 跳出小程序 | 不是小程序内播放，仍需 `feedId` | 中 | 仅能作为降级 |
| E. 自动抓取/下载转存 | 抓分享页或非公开接口 | 自建播放器 | 风控、登录态、版权、合规、稳定性都不可控 | 高 | **不建议** |
| F. 现有单链接原样复用 | 现有 `collect_url` | 公众号模板 | 误判渠道、错误元数据、错误模板 | 低但不可用 | **不可行** |

## 五、推荐方案

### 5.1 方案 A：H5 独立视频号收藏页（通用收藏）

定位：视频号内容索引与个人收藏夹，不是播放器。

首版流程：

1. 用户在微信视频号分享菜单复制链接；
2. 粘贴到收藏页，手工填写标题，选填作者、封面、日期、备注；
3. 系统只做链接识别、规范化、去重和本地保存；
4. 卡片显示“视频号”徽标、标题、作者、日期、备注；
5. 点击只提供“复制链接”，并提示“复制后回微信聊天打开”；
6. 提供 JSON 导出/导入，手机和电脑之间手动迁移。

不做：自动请求视频号页面、自动抓标题/封面、自动下载视频、iframe、`<video>` 直链播放。

### 5.2 方案 B：小程序 + 自有/关联视频号（完整播放）

适用：视频是你自己的视频号，或小程序与视频号同主体/关联主体。

- 从小程序后台/视频号助手取得 `finderUserName` 与 `feedId`；
- 用 `channel-video` 内嵌；
- 同主体可自动播放；
- 数据可存云数据库，按 `openid` 隔离。

这是唯一能稳定实现“小程序内播放”的通用路径。

### 5.3 方案 C：小程序通用收藏 + 可选 `feed-token`

适用：接受“部分内容可内嵌、其余跳转/复制”的混合体验。

数据字段：

```text
id
title
url
cover
author
tags
note
feedId            # 可选
feedToken         # 可选
finderUserName    # 可选
addedAt
lastVerifiedAt
```

详情页策略：

1. 有 `feedToken`：用 `channel-video` 内嵌播放；
2. 没有 `feedToken` 但有 `feedId`：用 `wx.openChannelsActivity` 跳转；
3. 两者都没有：复制链接，提示回微信打开。

关键点：

- `feedToken` 放在“高级选项”，不默认要求用户填写；
- `feedToken` 建议只存服务端/云数据库，不写进公开分享链接；
- token 失效时降级到复制/跳转，不要整条收藏不可用；
- 不承诺“任意视频都能内嵌”。

### 5.4 不推荐的方案

- 在 H5 里用 iframe 嵌入视频号分享页；
- 把视频号链接直接塞进 `<video>`；
- 抓取播放地址、下载视频再转存；
- 用非公开接口批量获取标题/封面；
- 把“任意他人视频号内嵌播放”作为产品卖点。

## 六、数据与页面设计

### 6.1 H5 数据模型

建议独立键 `jiye.channels.v1`，不要混入 `jiye.mine.v1`：

```text
platform: channels
kind: video
key: channels:<sph 稳定 ID 或规范化链接哈希>
url: https://weixin.qq.com/sph/...
title: 手工填写，必填
author: 手工填写，可空
cover: 手工填写图片 URL，可空
date: 手工填写，可空
note: 个人备注，可空
addedAt: ISO 时间
```

去重规则：优先 `/sph/` 后的稳定 ID；没有稳定 ID 时使用去掉追踪参数后的链接哈希；不要按标题去重。

### 6.2 小程序数据模型

```text
openid
favoriteId
title
url
cover
author
tags
note
feedId
feedToken
finderUserName
source
addedAt
lastVerifiedAt
```

存储方式：

- 只在这台手机使用：小程序本地缓存即可；
- 需要跨设备：微信云开发数据库或自有后端；
- 小程序与 H5 的 `localStorage` 天然不互通，若要求双端一致，必须做云同步或导入导出。

### 6.3 页面与交互

H5：

- 列表：封面/占位图、视频号徽标、标题、作者、日期、备注；
- 详情：大封面、标题、作者、备注、“复制链接”按钮；
- 微信外提示“需回微信观看”，但不拦截页面主体；
- 不直接跳转 `weixin.qq.com/sph/...`。

小程序：

- 添加页：粘贴链接、标题必填、作者/封面/备注选填；
- 高级项：`feed-token`（可选）；
- 详情页：有 token 用 `channel-video`，否则显示跳转/复制；
- 失败提示：明确“当前内容未提供内嵌参数，需回视频号观看”。

## 七、主体、审核与合规

### 7.1 小程序主体

- 同主体/关联主体：`channel-video` 可用 `feed-id`；
- 非同主体：必须是非个人主体小程序，才能用 `feed-token`；
- 个人主体小程序不能内嵌非同主体视频号内容，只能 `wx.openChannelsActivity` 跳转；
- `wx.openChannelsActivity` 无主体限制，但它是跳出小程序，不是内嵌播放。

### 7.2 审核与类目

- 小程序需要注册、认证、选择合适服务类目、提交审核；
- 如果定位为“个人收藏/索引”而不是公开视频内容库，审核解释成本更低，但不等于免资质；
- 具体类目和资质要求以提交时微信平台规则为准，不能预先承诺“肯定能过”。

### 7.3 内容合规

- 不下载、不转存、不代理视频文件；
- 不绕过登录、风控或权限；
- 不把视频号内容包装成自有内容；
- `feed-token` 不公开、不日志明文输出；
- 用户自填封面要注意版权。

## 八、风险清单

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 分享链接在 H5 白屏 | 用户以为页面坏了 | 不直接跳转，只复制链接 |
| 视频号被识别成公众号 | 错误徽标、错误模板 | 增加 `channels` 优先级识别 |
| 手工补录仍落成公众号 | 数据语义错误 | 视频号走独立平台/独立模板 |
| 任意视频无法取得 `feedToken` | 小程序内不能播放 | 明确降级到跳转/复制 |
| `feedToken` 24 小时权限窗口 | 运营成本高 | 只做少量固定内容，不做通用承诺 |
| 个人主体小程序不能内嵌非同主体 | 功能不可用 | 改用跳转，或升级非个人主体 |
| token 失效 | 播放失败 | 详情页降级，不整条报废 |
| 手机/电脑数据割裂 | 收藏不同步 | 云数据库或导出/导入 |
| 自动抓取依赖非公开接口 | 随时失效、账号风险 | 不纳入核心链路 |
| 页面被判“仅微信展示” | 外链被限制 | 不做硬拦截，保持浏览器可用 |

## 九、分阶段建议

### 第一阶段：H5 收藏索引

- 独立视频号收藏页/独立数据层；
- 粘贴链接、标题必填、备注/作者/封面选填；
- 本地保存、去重、复制链接；
- 导出/导入；
- 不做自动抓取，不做站内播放。

目标：先验证“是否真的需要一个视频号收藏夹”。

### 第二阶段：小程序自有内容

只有在“必须小程序内播放”成为明确需求，且视频为自己的视频号/同主体内容时才做：

- 小程序主体与视频号主体对齐；
- 取 `finderUserName` + `feedId`；
- 用 `channel-video`；
- 云数据库存收藏。

### 第三阶段：通用小程序收藏（可选）

只有接受“逐条 `feed-token`、非个人主体、24 小时权限窗口”才做：

- 通用收藏仍然只是索引；
- token 作为高级可选字段；
- 没有 token 就跳转/复制；
- 不把“任意视频内嵌播放”写进产品承诺。

### 明确不做

- 自动抓取视频号标题/封面；
- 下载/转存视频文件；
- H5 iframe 或 `<video>` 播放；
- 用非公开接口做批量采集；
- 把“仅微信内可用”做成硬限制。

## 十、验收指标

H5 首版：

- 视频号链接识别为 `channels`，不再误判公众号；
- 同一链接重复添加会去重；
- 无标题阻止保存；
- 卡片显示“视频号”徽标、标题、作者、日期、备注；
- 复制链接可用，点击不会直接跳转白屏；
- 微信内/微信外都能打开收藏页，不出现“仅微信可用”拦截；
- 导出后再导入，条目数量和字段不丢失；
- 不产生对视频号页面的自动请求或视频文件下载。

小程序版：

- 自有/同主体视频能用 `feed-id` 内嵌播放；
- 非同主体只有在提供 `feed-token` 时才内嵌，否则正确降级；
- token 失效、参数错误时有明确提示；
- 不公开 token，不日志明文输出；
- 收藏数据可按 `openid` 隔离；
- 不缓存、不转存视频文件。

## 十一、最终建议

**先做 H5 收藏索引；小程序只在“自有/关联视频号播放”成立时做完整版；不做任意他人视频号的自动内嵌承诺。**

一句话判断：

- 只要“收藏 + 提示回微信看”：H5 可行，独立收藏页最稳。
- 要“自己的视频号在小程序内播放”：可行，`channel-video` + `feed-id`。
- 要“任意他人视频号在小程序内播放”：官方没有可持续的通用参数路径，不建议做。
